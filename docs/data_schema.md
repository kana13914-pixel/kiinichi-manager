# 端末に保存するデータの形

決定は `docs/decisions.md` の D-043。コードの正本は `app/util.js` の `DB`（キーの一覧）と `MIGRATIONS`（形を変えるときの引き継ぎ）。
形を変えたら、このファイルと `SCHEMA`（版）を一緒に直す。

## 方針

- 保存先は端末の localStorage（ホーム画面のアプリの中だけ。Safari とは別。D-009）。読み書きは必ず `Store`（`app/util.js`）を通す。
- データのキーは `db.*`。`db.meta.schema` に形の版を持つ（今は 2）。アプリを開くたびに `migrateData()` が版を確かめ、古ければ引き継ぐ。
- 日付は `'YYYY-MM-DD'`。**1日の区切りは朝4時**（D-034。`todayKey()`）。時刻は `'HH:MM'`、時点は 1970 年からのミリ秒。
- 記録・日報は消さずに残す。完了したタスクだけ、完了日から7日で消す（D-031）。
- 量の見込み：記録は1日あたり約 0.5KB、日報は1件あたり約 1KB。10年分でも 5MB の上限に届かない。2MB を超えるようになったら保存先（IndexedDB）を見直す。

## データ（スプレッドシートに同期する対象。D-050 で送り始めた。送るだけ）

| キー | 形 | 説明 |
| --- | --- | --- |
| `db.tasks` | `[ { id, title, due, priority, subtasks, done, doneAt, createdAt, updatedAt, toReport } ]` | タスク。`priority` は `high`／`mid`／`low`／`null`（なし）。`subtasks` はミニタスク `[ { id, title, done, doneAt } ]`（1段だけ、10個まで。D-070）。どちらもない古いデータは「なし」「ミニタスクなし」として読む。`toReport` は完了したら日報に入れるか（D-059。ないものは false）。`due` は日付か `null`。`updatedAt` は最後に変えた時点（同期で「どちらが新しいか」を決める） |
| `db.reports` | `{ 日付: { mood, done, left, tomorrow, savedAt } }` | 日報。1日1件。`mood` は `good`／`normal`／`tired`／`null` |
| `db.records` | `{ 日付: { 種類: 値 } }` | 毎日の記録。値はふつう `{ time, at }`（`time` は押した時刻、`at` はその時点）、休憩は `[ { time, at }, … ]`（押した回数だけ）、「今日はなし」は `{ skipped: true, at }`（D-046）。種類は下の表 |
| `db.routine` | `{ weekday: { 項目: 'HH:MM' か null }, holiday: { … }, holidays: [曜日の番号], updatedAt }` | 毎日の時刻（D-048）。項目は `wake`・`breakfast`・`work_start`・`lunch`・`work_end`・`dinner`・`bath`・`sleep`。曜日は 0＝日〜6＝土 |
| `db.routineOverrides` | `{ 'YYYY-MM-DD': { 項目: 'HH:MM' か null } }` | 毎日の時刻をその日だけ変えたもの（D-060 ⑭, D-061）。null は「この日はなし」。60日より前は消す。スプレッドシートには「毎日の時刻」のシートに今日以降の分を1日1行で送る |
| `db.timer` の `custom` | `[ { id, name, minutes } ]` | 利用者が作ったタイマー |
| `db.timer` の `builtin` | `{ 用途別の id: 分数 }` | 用途別のタイマー（`work`・`break`・`bath`・`brush`）のうち、利用者が時間を変えたものだけ（D-044）。ないものは初めの時間 |

### 記録の種類（`db.records` の「種類」）

| 種類 | 表示 | ホームに出す時間帯 |
| --- | --- | --- |
| `wake` | 起きた | 4〜11時 |
| `breakfast` | 朝食 | 5〜11時 |
| `work_start` | 仕事開始 | 7〜13時 |
| `lunch` | 昼食 | 11〜15時 |
| `break` | 休憩（1日に何度でも） | 10〜19時 |
| `work_end` | 仕事終わり | 16〜23時 |
| `dinner` | 夕食 | 17〜23時 |
| `bath` | 入浴 | 19〜翌4時 |
| `brush` | 歯磨き | 20〜翌4時 |
| `sleep` | 就寝 | 21〜翌4時 |

右の列はホームに出す時間帯（既定の毎日の時刻のとき。D-046）。実際は設定の「毎日の時刻」の前後で決まる（D-048）。コードの正本は `app/app.js` の `RECORD_KINDS`。

## R5 の利用者の決定で足すもの（2026-11-18。D-060 ⑩⑪⑭。実装しながら上の表に移す）

迷う点は `NEEDS_HUMAN.md` の H-022 で利用者に確かめる。答えが出るまでは、ここに書いた「仮の答え」で作る。

### `db.routineOverrides`（D-060 ⑭。同期の対象。**実装済み**：上の表に移した）

```
{ 'YYYY-MM-DD': { wake: '08:30', breakfast: null } }
```

- 毎日の時刻を**その日だけ**変えたもの。日付は朝4時区切り（D-034）。項目は `db.routine` と同じ8つ
- 値が `'HH:MM'` ならその日だけその時刻、`null` なら「この日はなし」、項目が無ければ平日・休日の時刻のまま
- `Routine.timesFor(日)` がこれを先に見る。だから、ホームの記録ボタンの時間帯・声掛けの予約（D-049）・予定のリスト・次の予定（NEXT）・起きたときの一言は、すべて上書きを優先する（月表示は生活の時刻を出さないので関係しない）
- 60日より前の日付は、開いたときに消す
- スプレッドシートへは「毎日の時刻」のシートに、今日以降の上書きを1日1行で足して送る（仮の答え。H-022 ⑤）

### `db.weekly` の `reply`（D-060 ⑪。この端末だけ。**実装済み**：上の表に足した。D-063）

```
{ '2026-11-09': { text, at, firstSeen, reply: { text: '…', at, edits: 0 } } }
```

- 先週のひとことへの利用者の返事。300字まで。書いたあと1回だけ書き直せる（`edits` が 1 になったら直せない）
- 次の週のコメントを作るとき（`/api/weekly`）に、前の週のひとことと返事を `previous: { comment, reply }`（ひとことは600字、返事は300字で切る）として一緒に送る。返事が無い週は送らない。送信サーバーはそれを Claude への指示に「先週のひとことへの返事」として入れる（言い回しの好み・不満を反映するため）。作り直し（再生成）はしない
- 返事を送った直後は、定型のセリフ（`weekly_reply.*`。LLM は使わない）で短く受け答えする

### `db.stats`（D-060 ⑩。この端末だけ。利用者には見せない。**実装済み**：上の表に移した。D-062）

```
{
  days: {
    'YYYY-MM-DD': {
      notified: { meal: 2, break: 1, night: 1, sleep: 1, event: 0 },  // 声掛けの通知の数（種類ごと）
      missed:   { lunch: 1, bath: 1 },                                 // 予定の時刻があったのに記録が無かった
      skipped:  { breakfast: 1 },                                      // 「今日はなし」にした
      unused: true                                                     // その日、記録が1つも無い（アプリを使わなかった日）
    }
  },
  closedThrough: 'YYYY-MM-DD',   // missed・skipped を数え終えた最後の日
  lineShown: { 'pattern_check.lunch_missed': 'YYYY-MM-DD' }  // ホームのセリフを最後に出した日
}
```

- **notified**：声掛けの予約（`db.notify`）のうち、取り消されないまま予約の時刻を過ぎたものを「送った」とみなして、その日（キーの日付）に数える。種類はキーの最初の `:` より前（`meal`・`break`・`night`・`sleep`・`event`）。タイマーの通知は利用者が自分で始めたものなので数えない。送信サーバーで実際に届いたかまでは見ない（仮の答え。H-022 ⑥）
- **missed・skipped**：その日が終わってから（朝4時を過ぎて、次に開いたとき）数える。対象は毎日の時刻に予定のある記録（起きた・朝食・仕事開始・昼食・仕事終わり・夕食・入浴・歯磨き・就寝。休憩は数えない）。予定の時刻は、その日の上書きと、数えるときの平日・休日の時刻から決める
- **unused**：その日に記録が1つも無ければ、missed は数えず `unused: true` だけを残す（使わなかった日を「全部忘れた日」にしない。仮の答え。H-022 ①）
- **使い道1・週次コメント**：`weekSummary` に、その週の合計を数だけで足す（例「声掛けの通知：食事3回、休憩2回」「記録が無かった分：昼食2日」「使わなかった日：1日」）。日報の中身と同じく送信サーバーを通して Claude に送る（D-058）
- **使い道2・ホームのセリフ**：条件に当てはまったら、ホームを開いたときの時間帯の一言（`idle_greeting`）の代わりに、その条件のセリフを出す。最初の条件は「同じ食事の記録なしが3日続いた」（`pattern_check.<朝食|昼食|夕食>_missed`）。同じセリフは1日1回まで（`lineShown`）。文面は仮案（H-022 ③）
- 400日より前の日付は消す
- スプレッドシートには送らない（仮の答え。H-022 ②）
