# 第一印象の不満（「ダサい・もっさり」「らしくない」）への対応フロー — AI用

- 文書ID: R3-Q2-AI
- 目的: 利用者から抽象的な見た目の不満が来たとき、**言葉 → 測れる属性 → 原因 → 打ち手 → 検証**の順に処理するための手順書。
- 前提: このアプリの利用者は 1 人（開発依頼者本人）。評価者＝利用者。大規模なユーザー調査はしない。
- 関連: R3-Q1-AI（キィニチの事実）、R3-Q3-AI（今回の結論と実装指示）、ラウンド1の知識ベース（ルール ID V1〜M3）

---

## 1. 根拠となる知見（要点だけ）

| ID | 知見 | このフローでの使い道 |
| --- | --- | --- |
| E-01 | 見た目の魅力は約 50 ミリ秒で判断され、長く見た後の評価とよく一致する（Lindgaard ら 2006） | 「初見の感想」は気分ではなく、測る価値のある信号として扱う |
| E-02 | 第一印象は後の使いやすさ・信頼の評価にも影響する。第一印象を最もよく説明するのは**視覚的な複雑さ**で、色彩の豊かさは次点（Reinecke ら 2013, 450 サイト × 548 人） | 打ち手は「色を足す」より先に「面・線・密度の構成」を見直す |
| E-03 | 製品の質は「実用的な質（PQ）」と「快楽的な質（HQ）」で別々に知覚される。HQ は刺激（HQ-S：新しさ・大胆さ）と同一化（HQ-I：洗練・高級感・自分らしさ）に分かれる（Hassenzahl, AttrakDiff2） | 「ダサい」は HQ-I、「もっさり」は HQ-S（と一部 PQ）、「らしくない」は HQ-I の問題として分解する |
| E-04 | 見た目だけを見せた段階では、美しさの評価は HQ-I だけに左右された（Hassenzahl 2004 の要約） | 初見の「ダサい」には、使いやすさの改善では効かない。見た目の同一性を直す |
| E-05 | 典型性と新規性は両方とも好ましさを高め、互いに打ち消し合う。「最も進んでいて、なお受け入れられる」が好まれる（MAYA。Hekkert ら 2003）。分類が単純な対象では「受け入れられる側」に重みが寄る（2025 の追試） | 新しさは盛りすぎない。iPhone アプリとしての「型」（タブバー、時刻、ボタン位置）は保ったまま、表面の質感で新しさを出す |
| E-06 | 人は曲線の物を好み、鋭い角は脅威の手がかりとして扱われやすい（Bar & Neta 2006, 2007）。ただし直角と直線は身近さから好まれ、鋭い**鋭角**ほど脅威が増す（Friedenberg ら 2023） | 角を出すなら 45° の面取り（直線＋鈍角）に留め、鋭角のトゲは使わない。タップする物は特に |
| E-07 | 印象語の SD 法では「活動性」因子に「鋭い－鈍い」「角ばった－丸い」「速い－遅い」が入る（Osgood の意味空間。感性工学の基礎） | 「もっさり」を「丸い・鈍い・遅い」側への偏りとして扱い、形・線・動きで活動性を上げる |
| E-08 | 感性工学は、感性語（形容詞）をツリー状に分解して物理的な設計要素に対応づける（長町。タイプI：カテゴリ分類法） | §3 の変換表の作り方 |
| E-09 | 製品反応カード（118 語から 5 語選び、理由を話す。Benedek & Miner 2002） | 利用者本人の評価を 3 分で取る道具（§4.2） |
| E-10 | スタイルタイル：ムードボードより具体的、完成画面より軽い、色・文字・部品の見本（Warren 2011） | 方向性の比較は完成画面ではなくタイルで行う |
| E-11 | ジャンプ率（本文に対する見出しの文字の大きさの比）が高いと躍動的・若々しく、低いと落ち着き・高級感 | 「もっさり」には、最重要の 1 要素だけジャンプ率を上げる |
| E-12 | 表現力の強い UI は、好まれるだけでなく重要な要素を最大 4 倍速く見つけさせた（Google, Material 3 Expressive。46 研究・1.8 万人） | 「らしさ」と使いやすさは両立しうる。ただし主ボタンを目立たせる方向で使う |
| E-13 | モバイルの画面遷移はおよそ 300ms。400ms を超えると遅く感じる（Material の動きの指針）。入る動きは減速カーブ（例 `cubic-bezier(0.05,0.7,0.1,1)`） | 「もっさり」が動きの遅さ由来でないか確認する。新しい動きは 300ms 以内 |
| E-14 | ペルソナ5 の UI は主色（赤）以外の補助色をほぼ使わずに強い個性を出したが、初期案は「読めない」状態で何度も調整された | 個性は「強い主色＋形の一貫性」で出る。読みやすさの調整は必ず別工程で取る |
| E-15 | ゲーム UI の 4 分類：ダイエジェティック／メタ／空間／非ダイエジェティック（Fagerholt & Lorentzon 2009） | アプリの UI は非ダイエジェティックだが、「世界の素材感」を借りる（メタ的な装飾）ことはできる |
| E-16 | iOS 26 の Liquid Glass は「操作の層（浮いているコントロール）」と「内容の層」を分け、ガラスは操作の層にだけ使う | 流行の質感を全面に貼らない。PWA ではネイティブの Liquid Glass は使えないので追わない |

## 2. フロー全体

```
F1 受け取る → F2 言葉を属性に分解 → F3 いまを測る → F4 原因を部品単位で診断
→ F5 目標の印象を決める → F6 源泉（キャラ）からモチーフを選ぶ
→ F7 方向性を 2〜3 案（スタイルタイル） → F8 利用者が選ぶ
→ F9 トークンと決まりに落とす → F10 見本画面（ホーム）に実装
→ F11 同じ物差しで測り直す → F12 他の画面へ展開
```

各段の「完了条件」を満たすまで次へ進まない。F8 と、決定済み事項（docs/decisions.md）を覆す変更は利用者の確認が必要。

## 3. 各段の手順

### F1 受け取る
- 原文をそのまま記録する（言い換えない）。
- 付帯情報: どの画面か、端末（iPhone 15 / SE）、時刻帯（昼・夜）、初見か使い込んだ後か。
- 完了条件: 原文と付帯情報が `docs/feedback/` などに 1 件 1 行で残っている。

### F2 言葉を属性に分解（感性語の変換）

変換表（このアプリで頻出する言葉）:

| 利用者の言葉 | 対になる属性（SD 法の両極） | 主に効く質（E-03） | 疑う原因（部品単位） |
| --- | --- | --- | --- |
| ダサい | 野暮ったい⇔洗練された／安っぽい⇔上質／古い⇔新鮮 | HQ-I | 既定のままの見た目（初期値の角丸・ピル形）、装飾の質の低さ、文字の大小差が小さい、面が全部同じ扱い |
| もっさり | 重い⇔軽い／鈍い⇔鋭い／遅い⇔速い／ぼんやり⇔くっきり | HQ-S（＋PQ） | 大きな角丸と太い枠、低いジャンプ率、余白の多い大きな空箱、反応の遅さ、動きが長い |
| 市民会館みたい | ありきたり⇔独創的／保守的⇔大胆／公共施設的⇔個人的 | HQ-S, HQ-I | 左右対称の箱積み、無難な配色の 2 色だけ、模様・質感なし |
| らしくない | 無関係⇔そのキャラらしい／一般的⇔固有 | HQ-I | 源泉の特徴が色だけ、形・線・模様・動きに源泉がない |
| 子どもっぽい | 幼い⇔大人びた | HQ-I | 丸文字・丸い形・原色の多用 |
| うるさい | 騒がしい⇔静か／複雑⇔簡潔 | HQ-I（E-02 の複雑さ過多） | 装飾の数と場所が多い、差し色が広い |

- 完了条件: 不満 1 件につき 2〜4 対の属性が決まっている。

### F3 いまを測る（3 分でできる自己評価）
1. **5 秒テスト**: 画面を 5 秒だけ見せ、隠してから「覚えていること」「一言で言うと」を聞く。
2. **SD 評価（7 段階、-3〜+3）**: 次の 8 対を固定で使う（AttrakDiff2 の項目から本アプリ向けに抜粋＋キャラ適合の 1 対）。

| No | 左（-3） | 右（+3） | 質 |
| --- | --- | --- | --- |
| S1 | 野暮ったい | 洗練された | HQ-I |
| S2 | 安っぽい | 上質な | HQ-I |
| S3 | ありきたり | 独創的 | HQ-S |
| S4 | 保守的 | 大胆な | HQ-S |
| S5 | 重い・鈍い | 軽い・鋭い | HQ-S（活動性） |
| S6 | ごちゃごちゃ | すっきり | PQ |
| S7 | 読みにくい | 読みやすい | PQ |
| S8 | キィニチらしくない | キィニチらしい | HQ-I（固有） |

3. **反応カード**: 下の 24 語から当てはまるものを 5 語選び、理由を一言ずつ（118 語の原典から本アプリ向けに抜粋。肯定 60%・否定 40% の比率を維持）。
   - 肯定: 洗練された／新鮮／個性的／落ち着く／くっきり／頼もしい／楽しい／上質／わかりやすい／素早い／心地よい／大人っぽい／ワクワクする／親しみやすい
   - 否定・中立: ありきたり／古い／重たい／退屈／安っぽい／うるさい／子どもっぽい／冷たい／わかりにくい／未完成
- 完了条件: 改善前のスクリーンショットと S1〜S8 の点数と 5 語が残っている。

### F4 原因を部品単位で診断
次の 10 項目を、画面のスクリーンショットを見ながら 0〜2 点で採点し、根拠を 1 行書く（2＝問題大）。

| No | 観点 | 典型的な「もっさり・ダサい」状態 |
| --- | --- | --- |
| D1 | 形 | 全部が同じ角丸・ピル形。形の言語がない |
| D2 | 線 | 太い枠（1.5〜2px）、破線、全要素に枠 |
| D3 | 面の階層 | 地・カード・ボタンの明度差が小さい／全部が箱 |
| D4 | 色の構成 | 主色＋1 色だけ。差し色・引き締め色がない |
| D5 | 文字の階層 | ジャンプ率が低い（最大と本文の比が 2 未満）。ウェイトが 1〜2 種 |
| D6 | 質感・奥行き | 一色べた塗り。光・粒・重なりがない |
| D7 | 余白の意味 | 大きな空箱やプレースホルダが面積を占める |
| D8 | 固有のモチーフ | 源泉の形・模様・動きが 1 つもない |
| D9 | 動き | 動きがない、または長い・繰り返す |
| D10 | 実際の速さ | タップの反応が 100ms を超える、遷移が 400ms を超える、表示のがたつき |

- D10 が 2 点なら、見た目より先に性能を直す（「もっさり」が動作の遅さを指している可能性）。
- 完了条件: 2 点の項目が特定され、F2 の属性とつながっている。

### F5 目標の印象を決める
- S1〜S8 の目標値を決める。**新しさ（S3, S4）は +1〜+2 に留め、+3 を狙わない**（E-05）。読みやすさ（S7）は改善前より下げない（下限）。
- 一文のコンセプトにする（例:「静かな面に、金の細線。角は斜めに切り、差し色は小さく。」）。
- 完了条件: 目標値の表と一文コンセプト。

### F6 源泉からモチーフを選ぶ
- 源泉の事実文書（R3-Q1-AI §6）から、抽象化段階 L3（比率・角度・リズム）を中心に 5〜8 個選ぶ。L1（そのまま描く）は使わない。
- 選んだモチーフごとに「どの部品に、何個まで」を決める（1 画面 1 か所ルールの対象を明記）。
- 完了条件: モチーフ × 部品 × 上限 の表。

### F7 方向性を 2〜3 案（スタイルタイル）
- 各案で揃える項目: 地の色と光、面 3 段、金の使い方、角の形、線の太さ、文字（時刻・本文・ラベル）、模様 1 種、動き 1 種、主ボタン・副ボタン・セリフ面・カードの見本。
- 案の振り幅: A 控えめ（既存＋線と色）／B 折衷／C 大胆（ゲーム UI 寄り）。
- 完了条件: 3 案それぞれの見本（画像 1 枚）と、各案の予想 S1〜S8。

### F8 利用者が選ぶ
- 選択肢は画像付きで、1 問 1 決定。推奨案を先頭に置き、理由を一行添える。
- 決まったら docs/decisions.md に D 番号で記録（覆す既存決定があれば明記）。

### F9 トークンと決まりに落とす
- 色・形・線・文字・動き・模様を `:root` のトークンにする（生の値を画面ごとに書かない＝既存ルール M2-01）。
- 新しい色の組み合わせは `scripts/contrast_check.py` の表に足し、全組み合わせが基準以上であること（文字 4.5:1、部品の境界 3:1）。
- 完了条件: トークン表、決まりの ID、コントラスト表が docs/design.md に反映。

### F10 見本画面に実装
- まずホームだけに適用し、機能と既存テストを壊さない。
- 確認する状態: 朝・通知から開いた直後・記録後・夜・iPhone SE・動きを減らす設定。

### F11 測り直す
- F3 と同じ 5 秒テスト・SD 評価・反応カードを実施し、改善前と並べる。
- 判定: 目標を満たさない属性があれば F4 に戻る（全体のやり直しではなく、その属性に効く部品だけ直す）。
- 1 週間使った後にもう一度 S1〜S8 を取る（新しさは慣れで薄れる。残るのは同一化 HQ-I）。

### F12 他の画面へ展開
- 予定・タスク・タイマー・日報・設定に、同じトークンと部品をそのまま使う。画面ごとの特別扱いを作らない。

## 4. してはいけないこと（失敗パターン）

| No | 失敗 | 理由 |
| --- | --- | --- |
| X1 | 装飾を全部の部品に足す | 複雑さが第一印象を最も強く下げる（E-02）。装飾は 1 画面 1〜2 か所 |
| X2 | 公式素材・公式 UI を真似る | 権利上不可。加えて「似せた偽物」は安っぽく見える |
| X3 | すべての角を鋭くする | 鋭角は脅威の手がかり（E-06）。タップ対象は特に 45° の面取りまで |
| X4 | 差し色を広い面に使う | らしさは「小さく鮮やか」で出る（R3-Q1-AI §4）。広いと子どもっぽく、うるさい |
| X5 | ガラス風（ぼかし）を全面に | 操作の層だけに使う（E-16）。内容の層は不透明 |
| X6 | 長い・繰り返す動き | 400ms 超は遅く感じる（E-13）。冷静な人物像にも合わない |
| X7 | 一度に全部を変えて測らない | どの変更が効いたか分からない。F11 を省かない |
| X8 | 読みやすさを犠牲にする | 個性の強い UI でも読めない段階を経て調整されている（E-14）。S7 は下げない |
| X9 | 文字の大小差を全部上げる | ジャンプ率を上げるのは最重要の 1 要素（時刻など）だけ（E-11） |
