## 1. 診断：なぜ v6 は「ダサい・もっさり」「らしくない」のか

R3-Q2-AI §F4 の 10 観点で v6 ホーム（iPhone 15, 7:12）を採点。2＝問題大。

| No | 観点 | 点 | 根拠（v6 の事実） | 対応する印象 |
| --- | --- | --- | --- | --- |
| D1 | 形 | 2 | 角丸 12〜16px とピル形だけ。名前札・声を聞く・次の予定・記録ボタンが全部同じ「やわらかい箱」 | もっさり／市民会館 |
| D2 | 線 | 1 | 立ち絵の 2px 破線、全ボタンに 1px 枠 | ダサい（未完成感） |
| D3 | 面の階層 | 1 | 地 #1e4034 とカード #2a4b3f の明度差が小さく、どれも同じ重さ | もっさり |
| D4 | 色の構成 | 2 | 深緑＋金の 2 色だけ。黒の引き締めも差し色もない（キィニチの外見は 緑・黒・金＋青橙ライム白） | らしくない |
| D5 | 文字の階層 | 2 | 時刻 28px ÷ 本文 17px ＝ジャンプ率 1.65。ウェイトも 400/700 のみ | もっさり／ありきたり |
| D6 | 質感・奥行き | 2 | 一色べた塗り。光・粒・重なりがない（舞台の放射グラデは 6% で見えない） | 市民会館 |
| D7 | 余白の意味 | 2 | 破線の「立ち絵（仮）」が画面の約 45% を占める＝工事中の看板 | ダサい／未完成 |
| D8 | 固有モチーフ | 2 | キャラ由来の形・模様・動きが 0。らしさは色だけ | らしくない |
| D9 | 動き | 1 | 通知時の脈動 2 回のみ。セリフの入れ替えに動きなし | もっさり（静止画的） |
| D10 | 実際の速さ | 0 | 表示 3 秒以内のテストあり、遷移の遅さは見られない | — |

結論: 「もっさり」は動作速度ではなく**形と文字の活動性の低さ**（D1, D5）、「ダサい」は**既定値のままの見た目と工事中の枠**（D1, D2, D7）、「らしくない」は**色以外の源泉要素の欠如**（D4, D8）が主因。使いやすさ（PQ）はすでに高いので、直すべきは快楽的な質（HQ-S・HQ-I）。

## 3. 見た目の決まり（アプリ全体。ID で引用すること）

### 3.1 色 CR-C

| ID | 決まり |
| --- | --- |
| CR-C01 | 面は 3 段＋最奥：地（深緑のグラデーション）→ セリフ面・カード（黒 90%/55%）→ 最奥（`--color-ink` タブバー・控えめボタンの地） |
| CR-C02 | 金（`--color-accent`）の**塗り**は画面に 1 つ（主ボタン）。金の**文字**は名前と選択中タブだけ（既存 V3-08 を維持）。金の**線**（`--color-gold-line` 55%、`--color-gold-faint` 18%）は装飾として使ってよい |
| CR-C03 | 差し色（ライム・青・橙・白）は装飾専用で、画面面積の 2% 以内。文字色には使わない（例外: 記録済みの文字＝`--color-success`＝ライム） |
| CR-C04 | 多色（差し色 4 つを並べる）は 1 画面 1 か所。ホームでは「次の予定」の数珠 |
| CR-C05 | 夜（22〜4 時）は面を一段暗くし、上からの光を消して足元に淡い火（`--color-ember-glow`）を置く |

### 3.2 形 CR-S

| ID | 決まり |
| --- | --- |
| CR-S01 | 面とボタンは**左上と右下の 2 角を 45° に落とす**（`clip-path`）。量は `--cut-s` 6px（小ボタン・トースト）／`--cut-m` 10px（記録ボタン・カード）／`--cut-l` 14px（セリフ面） |
| CR-S02 | 縁のあるボタンは「外側を縁の色で塗る＋`::before` を 1px 内側に塗りの色で重ねる」で斜めの縁を描く（`border` は `clip-path` で欠けるため使わない） |
| CR-S03 | 角丸とピル形は新しく作らない。入力欄（`input`）だけは iOS の慣習に合わせ角丸 8px を残す |
| CR-S04 | 鋭角（45° より鋭いトゲ）は使わない（Bar & Neta 2006 / Friedenberg 2023：鋭角は脅威の手がかり） |

### 3.3 線・模様 CR-L

| ID | 決まり |
| --- | --- |
| CR-L01 | 区切りは 1px の金の細線（`--color-gold-line` / `--color-gold-faint`）。破線は使わない |
| CR-L02 | 段々の帯（`img/fret.svg`、自作の階段状の幾何学）はタブバーの上辺の 1 か所だけ |
| CR-L03 | 「次の予定」は箱にせず、上下の細線＋左の数珠で区切る |
| CR-L04 | 名前は札（枠付きの小箱）にしない。「ライムの菱形＋名前＋右へ消える金の線」 |

### 3.4 文字 CR-T

| ID | 決まり |
| --- | --- |
| CR-T01 | ジャンプ率を上げるのは時刻だけ：`--fs-display` 48px・ウェイト 300・字間 -0.02em・等幅数字。日付は時刻の上に 13px（D-019 Q3 の 28px を改訂 → D-021） |
| CR-T02 | 英字の小見出し（`.label-en`）は 11px・太字・字間 0.18em・`--color-text-tertiary`。読み上げない（`aria-hidden`）。**各画面に 1 つだけ**：ホームは「次の予定」の `NEXT`、ほかの画面は見出し（h1）の上に `SCHEDULE`／`TASKS`／`TIMER`／`REPORT`／`SETTINGS`。カードの見出しや新しい画面で増やすときも 1 画面 1 つを守る（D-021 Q-R3） |
| CR-T03 | 名前は字間 0.14em。本文・セリフは従来どおり 17px / 行間 1.7 |
| CR-T04 | Web フォントは使わない（システムフォントの細いウェイトで十分。読み込みの遅さ＝もっさりを避ける。公式フォントは禁止） |

### 3.5 地・質感 CR-B

| ID | 決まり |
| --- | --- |
| CR-B01 | 地は上（`--color-bg-top`）から下（`--color-bg-bottom`）へ暗くなる縦グラデーション（断崖・足元ほど黒） |
| CR-B02 | 昼は上から淡いライムの光（`--bg-glow`、12%） |
| CR-B03 | 全面に白 4.5% の粒（`img/grain.svg`）で紙のような質感。ガラス風のぼかしはセリフ面だけ（既存） |

### 3.6 立ち絵なしの「気配」CR-P

| ID | 決まり |
| --- | --- |
| CR-P01 | 破線の「立ち絵（仮）」は出さない。`#portrait` は立ち絵の枠として残し、立ち絵がない間は紋章（`img/canopy-emblem.svg`）を背景に出す |
| CR-P02 | 紋章は自作の幾何学：太陽の輪＋16 本の光＋四弁＋中央の菱形＋ロープの弧とフックの巻き。公式の元素マーク・紋章に似せない |
| CR-P03 | 舞台の上部から 3 本の吊り線（菱形・羽根の先端。`img/canopy-vines.svg`）、右端に縁取りだけの縦書き `KINICH`（`.stage-mark`、高さは舞台の 17% まで） |
| CR-P04 | 立ち絵を入れるとき: `#portrait` に `data-art="ready"`、`role="img"`、`aria-label` を付け `aria-hidden` を外す → 紋章は自動で消える。吊り線と縦書きは残してよい |

### 3.7 動き CR-M

| ID | 決まり |
| --- | --- |
| CR-M01 | セリフが替わるたび、左から 12px 引き寄せるように 260ms で入る（`cubic-bezier(0.05,0.7,0.1,1)`）。app.js で `.line-enter` を付け直す |
| CR-M02 | 新しい動きは 300ms 以内・1 回きり。繰り返す動きは通知時の脈動 2 回（既存）だけ |
| CR-M03 | 動きを減らす設定ではすべて止める（既存の `prefers-reduced-motion` で一括） |

### 3.8 アクセシビリティの守り CR-A（変えてはいけない）

| ID | 決まり |
| --- | --- |
| CR-A01 | 文字 4.5:1、部品の境界 3:1。新しい組み合わせは `scripts/contrast_check.py` に追加済み（`line` は地の最も明るい所でも 3.21:1） |
| CR-A02 | タップ領域 44px 以上、記録ボタン 52px（既存のまま） |
| CR-A03 | 装飾（紋章・吊り線・縦書き・NEXT・菱形・数珠・帯）は読み上げない |
| CR-A04 | iPhone SE（375×667）で 1 画面に収まる（舞台が縮む。縦書きは `cqh` で縮む） |

### 3.9 禁止 CR-X

- CR-X01 キィニチ・アハウ本人の描画、公式素材・公式 UI・公式フォント・ボイスの利用
- CR-X02 装飾を全部品に足す（1 画面 1〜2 か所）
- CR-X03 差し色を広い面・文字に使う
- CR-X04 ガラス風を全面に使う

### Q-R1 の判断（40px と 48px の比較）

参考実装で `--fs-display` だけを変え、iPhone 15（393×852）と SE（375×667）で同じ時刻（7:12）を撮って測った（`images/clock_40px_vs_48px.png`）。

| 観点 | 40px | 48px | 判定 |
| --- | --- | --- | --- |
| ジャンプ率（時刻 ÷ 本文 17px） | 2.35 | 2.82 | 「もっさり」の主因 D5 を直す力は 48px が大きい |
| 見出し行の高さ | 61px | 69px | +8px |
| 舞台の高さ（SE） | 231px | 223px | −3.5%。紋章が少し縮むだけで、はみ出しなし |
| 時刻の見た目の重さ（明るい画素の量。2 行のセリフを 1 とした値） | 約 0.48 | 約 0.69 | どちらもセリフより軽い。主役（セリフ）を奪わない |
| 装飾との上下関係（iPhone 15） | 縦書き KINICH（最大 72px）の方が目立ち、**情報より飾りが勝つ** | 時刻と KINICH が左上と右端で釣り合う | 48px が正しい階層 |
| 一瞥での読み取り（起床直後） | 良い | より良い | アプリの役割（時間の管理）と人物像 K-P02（数字を大きく正確に）に合う |

結論: 48px は SE でも収まり、セリフより軽いまま、飾りより強い。40px は飾り（KINICH）が情報（時刻）に勝つ逆転が起きるため不採用。細字（300）なので大きくしても重く見えない。
