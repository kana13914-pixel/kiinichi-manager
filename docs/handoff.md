## 4. 利用者との進め方（ファイルに書いていない約束）

- 会話は日本語
- **1画面ずつ**作り、公開して実機確認を頼み、「問題なし」の返事をもらってから次へ進む
- 実機確認の頼み方：設定画面に出る版（例「版：phase1-v10」）を最初に確かめてもらう。手順の全文は roadmap に書き、チャットには要点だけを書く。結果を受け取ったら roadmap の該当画面に「実機結果（日付）」を書き足してコミットする
- 選択肢を出すときは、推奨を1つめに置き「（推奨）」と書く。利用者はこれまで推奨をそのまま選ぶことが多い
- 利用者が「要相談」と書いた項目は、作る前に選択肢（推奨を1つめ）で1つずつ決める。細部（日数の数え方など）は決めた内容を報告に書く
- 仮のセリフ（仮案）は利用者が言い回しを確かめるまで「仮案」のままにする。作った画面の確認を頼むときに、仮案がどこに出るかも伝える
- 合言葉（APP_TOKEN）・ntfy のトピック名・利用者のメールアドレスは、チャットにもリポジトリにも書かない（D-008、`docs/cloudflare_setup.md`）

## 5. 1画面を作るときの手順（毎回やること）

1. 画面の中身：`app/index.html` の該当 `view`、画面ごとの JS（`app/tasks.js` や `app/report.js` を手本にした IIFE。日付は `util.js` の `todayKey`、保存は `Store`、取り消しの表示は `ui.js` の `makeToast`、描き直しは `onShow` を使う）、`app/style.css` の「各機能画面の共通部品」の後ろにその画面の節を足す。色・大きさはトークンだけを使う（`tests/test_style.py` が確かめる）
2. セリフを足したら `python3 scripts/build_dialogue.py` で JSON を作り直す
3. 版を上げる：`app/app.js` の `APP_VERSION` と `app/sw.js` の `CACHE_VERSION` を同じ値にする。新しい JS は `app/sw.js` の `ASSETS` にも足す
4. 新しいファイルは `docs/README.md` の表に足す（載っていないと `tests/test_docs_index.py` が落ちる）
5. 決めたことは `docs/decisions.md` に追記する。**新しい行は最後の D 行のすぐ後（「## 記入例」より前）に入れる**
6. テストを足す：`tests/test_pwa.py` の `clock_page(hour, minute, query, size, safe, day, init_script)` で時刻と保存データを決めて開ける（例：`tasks_page`、`report_page`）。最低限：保存と再読み込み後の保持、空入力の扱い、金の塗りが1つ、入力欄の文字16px以上、幅375pxで横にはみ出さない
7. 2つのテストを両方とも通す（コマンドは `CLAUDE.md` の末尾）
8. 画面写真で見た目を確かめる（Playwright で幅375と393。`full_page=True` で撮ると下のタブバーが写真の途中に写るが、固定表示のための見え方で不具合ではない）
9. roadmap の該当画面に「実装済み・自動テスト・実機確認手順」を書く
10. コミット（1コミット＝1つの検証可能な変更）して push、公開を確かめてから利用者に実機確認を頼む

## 6. 作業環境のくせ・つまずいたこと

- **偽の時計を使う画面テスト**（`page.clock`）で、本当の通信（`route` の応答）を待つものは、手元では通っても GitHub Actions では順番が変わって落ちることがある。通信の結果を待ってから時計を進める（少しずつ `run_for` して条件を確かめる）。2026-11-17 に2件で起きた
- **公開の確認**：`gh api` の Pages API はプロキシで止められる。push の約1分後に、WebFetch で `https://kana13914-pixel.github.io/kiinichi-manager/app/sw.js?check=<版>` を読み、`CACHE_VERSION` が新しい版になっているかで確かめる（`?check=` を変えるとキャッシュを避けられる）。作業環境のネットワークの設定で `github.io` が開けないときは（2026-11-19 に起きた）、GitHub の Actions の一覧で、その push の「pages build and deployment」と「test」が success になったかで確かめる
- **画面テスト**：Chrome（`/usr/bin/google-chrome`）は入っているが、Python の Playwright は入っていないことがある（`ModuleNotFoundError: No module named 'playwright'` で画面テスト全体が始まらない）。`pip install -r requirements-dev.txt` で入れる（リポジトリを汚したくなければ `pip install --target <一時フォルダ>` して `PYTHONPATH` に足す）。push すれば GitHub Actions でも両方のテストが走る
- **変更を一時的に戻して見た目を比べるとき**は、整理の前後で画面写真を撮り、ファイルを `cmp` で比べる（角丸の縁で1〜数ピクセルのゆらぎは出る）
- **変更を一時的に戻して試すとき**は `git stash` を使わない（未コミットの `app/style.css` の変更を一度失いかけた）。ファイルを `/tmp` にコピーして戻す
- **画面テストで時刻を大きく進めるとき**は `page.clock.run_for` ではなく `page.clock.fast_forward` を使う（run_for は毎秒のタイマーを全部実行するので、数時間ぶん進めると終わらない）
- **確認ダイアログ**（`confirmDialog`）の結果は非同期で届く。テストでは「削除する」を押したあと、トーストが出るのを待ってから確かめる
- **Node のテスト**で vm の中で作ったオブジェクトを `deepEqual` で比べると、見た目が同じでも失敗する。`JSON.parse(JSON.stringify(x))` にしてから比べる
- **斜めに切った部品**（`clip-path`）は `border`・`box-shadow`・`outline` が欠ける。縁や強調の描き方は `docs/visual_rules.md` の CR-S02、CR-S05
- **iPhone で入力欄を押すと拡大される**のを防ぐため、入力欄（`input`・`textarea`）の文字は16px以上にする（`app/style.css` の `input, textarea, .field` の規則）
- **Cloudflare のコネクタ**（利用者がチャットにつないだ場合）は読み取り用。`workers_get_worker_code` に `kiinichi-push` を渡すと、デプロイ中のコードが新しい版かを確かめられる。デプロイはできない（D-029 ③）
- **Cloudflare の作業を頼むとき**は、「今ある `kiinichi-push` を開いて」と Worker の名前をはっきり書き、`docs/cloudflare_setup.md` の作業する節の番号だけを示す。2026-11-17 に、手順書の最初（作る手順）から読まれて、使わない Worker・KV・D1（`…01`）が作られた
- **送信サーバーを変えたとき**は、利用者に Cloudflare への貼り付け直しを頼む（`docs/cloudflare_setup.md` の 7）。PWA 側は、古い送信サーバーでも困らない作りにする（新しい API は 404 になるので、それを画面に出す）
- **フォームが下のタブバーに隠れる**ことがある。タスク画面では `scroll-margin-bottom` と `scrollIntoView` で直した（`app/tasks.js`）。R6 でタスクのフォームは一覧の上に移した（`block: 'nearest'`）
- **画面写真のレビュー**：リポジトリの外に撮影用の小さなスクリプトを置き、`page.clock.install` で時刻を固定、`add_init_script` で `db.*` にデータを入れ、`--safe-top`／`--safe-bottom` を上書きして 393×852（59/34）と 375×667（20/0）で撮る。スクロール中（`window.scrollTo`）も撮ると、ステータスバーの下の透けなどが分かる（R6）
- **テストを並べて走らせると**、重い画面テストが時間の都合でまれに落ちることがある（R6 で 1 回。順に走らせ直すと通った）。コミットごとに確かめるときは1つずつ順に走らせる
- **CSP（D-076 ③）**：`index.html` に CSP があるので、テストで見た目を足すときは style タグ（`add_style_tag`）ではなく CSSOM（`style.setProperty`・`insertRule`）を使う。テストの配り方（`tests/test_pwa.py` の `QuietHandler`）は Playwright の待ち合わせのため eval だけ許す。公開と同じ CSP で確かめたいときは `/strict/` の下を開く。通信先を足すとき（新しい外部サービス）は CSP の `connect-src` にも足す。画面の route は Service Worker の取得を素通りすることがあるので、差し替えは `ctx.route` を使う
- **コミットの末尾**に付ける行はチャットの指示に従う（これまでは `Co-Authored-By:` と `Claude-Session:` の2行）
