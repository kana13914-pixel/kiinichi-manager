# ロードマップ

フェーズは上から順に進める。各タスクの完了条件を満たしたらチェックし、`docs/decisions.md` に追記すべき決定があれば追記する。止まった場合は `NEEDS_HUMAN.md` へ。

## フェーズ0: 技術検証（最優先・最初に実施）

最大のリスクは「自発的な声掛け」を成立させる通知経路。ここを最初に潰す。

- [ ] 最小のPWAを作成し、ホーム画面に追加した状態で通知が届くか確認する
  - 完了条件：Pushover/ntfy経由で送った通知が、ホーム画面に追加したPWAに届く
  - 人間作業が必要：実機での通知許可操作、サービスのアカウント作成（`NEEDS_HUMAN.md`参照）
- [ ] 通知をタップして開いた後、ボタン操作1回で音声が再生されるか確認する
  - 完了条件：タップ→画面表示→ボタン1回で音声ファイルが再生される
- [ ] 画面を閉じた状態で、指定時刻に通知が届くか確認する
  - 完了条件：アプリを完全に閉じた状態から、設定時刻±60秒以内に通知が届く

3点とも成立しない場合、`docs/decisions.md` に結果を記録したうえで作業を止め、`NEEDS_HUMAN.md` に方針転換の判断を依頼する（候補：通知をPushover/ntfyに完全依存する形に割り切る、またはSwiftでのネイティブ化を検討する）。

## フェーズ1: 画面設計

- [ ] ホーム画面のレイアウトを決める（初期表示要素、操作導線）
  - 完了条件：ワイヤーフレーム相当のHTML/CSSが動作し、`docs/spec.md`のホーム機能の完了条件を満たす
- [ ] 各機能画面（スケジュール・タスク・タイマー・日報）の見た目と操作を決める
- [ ] 通知許可を促す初回導線をUIに組み込む

## フェーズ2: データ設計

- [ ] ローカル保存（localStorage/IndexedDB）のデータ構造を決め、`docs/decisions.md`に記録する
- [ ] GAS経由でのスプレッドシート同期の仕組みを実装する
  - 完了条件：ローカルで行った変更が、一定時間内にスプレッドシートに反映される
- [ ] Googleカレンダーとの連携範囲を決めて実装する

## フェーズ3: 試作品制作

- [ ] ホーム画面と会話・リアクションの最小実装
  - 完了条件：`docs/spec.md`の朝・仕事開始のトリガーが、セリフ集に基づいて動作する

## フェーズ4: 機能追加

- [ ] タスク機能の実装
- [ ] スケジュール機能の実装（カレンダー連携込み）
- [ ] タイマー機能の実装（通知連携込み）
- [ ] 日報機能の実装
- [ ] 夕方のLLM連携（予定見直し提案）の実装
  - 完了条件：LLM呼び出しがサーバー経由で行われ、クライアントにAPIキーが含まれていない
